Introduction to Operating Systems

Covers the overview, classification, structuring approaches, services, system calls, virtual machines, and design/implementation of operating systems — with diagrams for the concepts that are easiest to lose in prose.

01 Overview of Operating Systems

An Operating System (OS) is system software that sits between the user/application programs and computer hardware. It manages hardware resources and provides a convenient, efficient environment for executing programs.

• Goals of an OS

  • Convenience — makes the computer easier to use.
  • Efficiency — permits efficient use of hardware resources.
  • Ability to evolve — allows effective development, testing, and introduction of new functions without disturbing existing service.

• Core functions

FunctionWhat it does
Process managementCreation, scheduling, termination, and synchronization of processes
Memory managementAllocation/deallocation of main memory, address translation
File managementCreation, deletion, organization, and access control of files
I/O / device managementUniform interface to diverse hardware via device drivers
Security & protectionControls access to resources; isolates processes from each other
Exam tip: if asked "define OS," lead with "a resource manager and an extended machine / virtual machine that hides hardware complexity." Both views (resource manager vs. abstract machine) are commonly asked to contrast.

02 Types of Operating Systems

Batch OS

Jobs with similar needs are grouped and run as a batch, without user interaction during execution. Reduces idle CPU time between jobs but no interactivity.

Multiprogramming OS

Several jobs reside in memory simultaneously; CPU switches to another job whenever the current one waits on I/O — maximizes CPU utilization.

Multitasking / Time-Sharing OS

Extension of multiprogramming — CPU time is divided into small slices (time quantum) so multiple users get the illusion of simultaneous, interactive access.

Multiprocessing OS

Two or more CPUs share the same memory and bus, running tasks in parallel — increases throughput and provides fault tolerance.

Distributed OS

Manages a group of physically separate, networked computers as a single system, sharing resources transparently to the user.

Real-Time OS (RTOS)

Guarantees response within a fixed deadline. Hard RTOS — missing a deadline is a system failure (e.g. airbag control). Soft RTOS — deadlines are desirable but not fatal (e.g. video streaming).

03 Operating System Structures

Structuring is about how OS components are organised internally — it affects reliability, performance, and ease of extension.

• Simple / Monolithic structure

All OS functionality (scheduler, file system, drivers, memory manager) runs as one large program in kernel mode. Fast (no inter-module call overhead) but hard to maintain — a bug in one part can crash the whole system. Example: original MS-DOS, early UNIX.

• Layered approach

OS is divided into layers, each built on the one below; each layer only uses functions of the layer directly beneath it.

• Microkernel

Only essential functions (IPC, basic scheduling, minimal memory management) stay in the kernel; file systems, device drivers, and other services run as user-mode processes. More reliable and secure (a failing service doesn't crash the kernel) but slower due to frequent user–kernel message passing. Example: QNX, Minix.

• Modules (loadable kernel modules)

Kernel has a core set of components and dynamically links in additional services (modules) at runtime — combines monolithic performance with microkernel-like extensibility. Example: modern Linux, Solaris.

• Hybrid systems

Combine elements of monolithic, microkernel, and modular approaches for a practical balance of performance and modularity. Example: macOS/XNU, Windows NT kernel.

04 Operating System Services

Services an OS provides fall into two groups: those that help the user, and those that ensure efficient system operation.

User-facing services

  • User interface — CLI, GUI, or batch interface
  • Program execution — load, run, and end programs; handle errors
  • I/O operations — since users can't control I/O devices directly
  • File-system manipulation — read, write, create, delete files/directories
  • Communications — data exchange between processes, same or different systems (via shared memory or message passing)
  • Error detection — detect and (where possible) correct errors in CPU/memory, I/O, or user programs

System-facing services

  • Resource allocation — allocate CPU, memory, storage among multiple users/jobs
  • Accounting — track which users use how much and what kind of resources
  • Protection & security — control access to resources; guard against unauthorised access

05 System Calls

A system call is the programming interface through which a process requests a service from the OS kernel — it is the only legitimate entry point into kernel mode.

• Categories of system calls

CategoryPurposeExamples
Process controlCreate, terminate, manage processesfork(), exec(), exit(), wait()
File managementCreate, read, write, delete filesopen(), read(), write(), close()
Device managementRequest/release devices, read/writeioctl(), read(), write()
Information maintenanceGet/set system data, time, dategetpid(), alarm(), sleep()
CommunicationSend/receive messages between processespipe(), shmget(), send(), recv()
ProtectionControl access to resourceschmod(), umask(), chown()

• Passing parameters to the OS

  • In registers — fast, but registers are limited in number and size
  • In a block/table in memory, with its address passed in a register — used when parameters exceed register capacity
  • Pushed onto/popped off the stack by the program and the OS
Distinguish clearly: a system call is a request to the kernel; an API (e.g. Win32 API, POSIX) is a set of library functions programmers actually call, which internally invoke system calls.

06 Virtual Machines

A Virtual Machine (VM) creates the illusion that a process (or an entire OS) has its own dedicated hardware, by using a layer — the hypervisor / Virtual Machine Monitor (VMM) — to abstract the physical hardware into several isolated virtual ones.

• Types of virtualization

TypeDescriptionExample
Type 1 (bare-metal)Hypervisor runs directly on hardware; guest OSes run above itVMware ESXi, Xen
Type 2 (hosted)Hypervisor runs as an application atop a host OSVMware Workstation, VirtualBox
Para-virtualizationGuest OS is modified to be aware it's virtualized, for better performanceXen (paravirt mode)
OS-level (containers)Single kernel, isolated user-space instances — lighter than full VMsDocker, LXC

• Why use VMs?

  • Isolation — a crash in one VM does not affect others
  • Run multiple OSes on one physical machine — efficient hardware utilisation
  • Easy to test, snapshot, migrate, and back up entire systems
  • Useful for server consolidation, cloud computing, and OS development/testing

07 Operating System Design and Implementation

• Design goals

User goalsSystem goals
Convenient to useEasy to design, implement, and maintain
Easy to learnFlexible, reliable, error-free
Reliable, safe, fastEfficient use of resources

These two goal sets sometimes conflict — e.g. maximum convenience for the user can mean lower system efficiency — and design is a balancing act between them.

• Mechanisms vs. policies

Mechanism — how to do something (the implementation). Policy — what is to be done (the decision).

Example: a timer is the mechanism ensuring CPU protection; the length of the time quantum it enforces is a policy decision. Separating the two lets policy change without touching the mechanism.

• Implementation considerations

  • Early OSes were written entirely in assembly language for speed and hardware control.
  • Modern OSes are written mostly in higher-level languages (C, C++), with small time/hardware-critical portions in assembly — trades a little performance for portability, readability, and easier debugging.
  • Implementation approach usually follows the chosen structure: monolithic, layered, microkernel, or modular (see Section 3) — the structuring decision and the implementation strategy go hand in hand.
